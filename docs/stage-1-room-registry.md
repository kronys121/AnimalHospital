# Этап 1. RoomRegistry

`src/shared/RoomRegistry.lua` — единственное место, которое знает, какие
лечебные кабинеты существуют и что происходит с пациентом внутри. Всё
остальное (ресепшн, цикл смены, мини-игры) обращается к кабинетам только
через этот модуль. Поэтому кабинет можно переключить с заглушки на настоящую
мини-игру, не трогая никакой другой код.

Куда положить: `ReplicatedStorage` → папка `Shared` → ModuleScript
`RoomRegistry`.

## Содержимое реестра

| RoomId | name | Номер | Состояние |
| --- | --- | --- | --- |
| `BasicMedical` | Basic Medical / DNA | 1 | заглушка |
| `XRay` | X-Ray | 2 | заглушка |
| `HeartMonitor` | Heart Monitor | 7 | заглушка |
| `Surgery` | Surgery | 8 | заглушка |

В реестре только четыре лечебных кабинета. Lobby, Reception, Corridor и
BreakRoom — это места в мире, а не комнаты, куда направляют пациента, поэтому
их здесь намеренно нет.

В роадмапе у `BasicMedical` стоит `isImplemented = true`, но на этапе 1
мини-игры ещё не существует — поставить флаг сейчас значило бы соврать и
подвесить цикл. Все четыре кабинета — заглушки; `BasicMedical` станет
`true` на этапе 5 автоматически, когда его мини-игру передадут в
`setHandler`.

## Заглушки

Кабинет с `isImplemented = false` «лечит» пациента случайным исходом через
`STUB_TREATMENT_SECONDS` (5 секунд), с шансом излечения 70%. Цикл пациента
никогда не зависает в ожидании мини-игры, которой ещё нет.

## Исходы

`RoomRegistry.Outcome`:

- `Cured` (`"cured"`) — пациент вылечен.
- `Died` (`"died"`) — пациент потерян.
- `Failed` (`"failed"`) — обработчик упал с ошибкой или вернул мусор. Это
  значит «кабинет сломан», а не «пациент проиграл», и всегда попадает в лог
  через `warn`. Кабинет при этом освобождается, смена не встаёт.

## API

| Функция | Назначение |
| --- | --- |
| `get(roomId)` | запись кабинета или `nil` |
| `getIds()` | копия списка id в фиксированном порядке |
| `getRooms()` | записи кабинетов в том же порядке |
| `isFree(roomId)` | свободен ли кабинет |
| `pickRandomRoom(includeBusy)` | случайный кабинет; по умолчанию только свободные, `nil` если все заняты |
| `getModel(roomId)` | модель комнаты в Workspace |
| `getEntryPoint(roomId)` / `getInteractionZone(roomId)` | маркеры из этапа 0 |
| `sendPatient(roomId, patient, onComplete)` | отправить пациента; `false`, если кабинет занят или неизвестен |
| `setHandler(roomId, handler)` | подменить заглушку на мини-игру |
| `describe()` | текстовая сводка по реестру |
| `runSelfTest()` | прогнать по одному пациенту через все кабинеты |

Порядок обхода фиксирован (`BasicMedical`, `XRay`, `HeartMonitor`, `Surgery`):
`pairs()` не гарантирует порядок, а смена, которая каждый раз обходит кабинеты
по-разному, невоспроизводима при разборе бага.

Модели ищутся по атрибуту `RoomId`, а не по имени инстанса, чтобы
переименование модели в Studio не ломало маршрутизацию молча.

## Занятость кабинетов

Каждый кабинет одновременно обслуживает одного пациента. `sendPatient`
возвращает `false`, если кабинет занят, а `pickRandomRoom` по умолчанию
пропускает занятые. Это заранее закрывает проблему из этапа 8 (два пациента
в параллельной обработке не должны конфликтовать).

Кабинет освобождается **до** вызова `onComplete`, поэтому медленный или
падающий колбэк не может заклинить комнату.

## Подмена заглушки на мини-игру

Это и есть смысл реестра. Этап 5 делает так для `BasicMedical`, этап 8 —
для `XRay`, и ни один другой файл при этом не меняется:

```lua
RoomRegistry.setHandler("BasicMedical", function(patient, room)
    -- мини-игра, можно yield-ить сколько угодно
    return { status = RoomRegistry.Outcome.Cured }
end)
```

`setHandler` сам переводит `isImplemented` в `true`. Обработчик выполняется
на отдельном потоке под `pcall`; если он упадёт, кабинет освободится, а
исходом станет `Failed`.

## Как проверить в Studio

Скрипт сборки (`src/server/BuildHospital.server.lua`) после постройки
здания сам вызывает `RoomRegistry.runSelfTest()`, если модуль на месте
(флаг `RUN_ROOM_REGISTRY_CHECK` в конце файла). В Output должно появиться:

```
RoomRegistry:
  BasicMedical  room 1   stub         model found    free
  XRay          room 2   stub         model found    free
  HeartMonitor  room 7   stub         model found    free
  Surgery       room 8   stub         model found    free
[RoomRegistry] XRay -> cured
[RoomRegistry] BasicMedical -> died
...
```

Четыре строки с исходами приходят примерно через 5 секунд после запуска, в
произвольном порядке и с произвольными исходами. Если вместо `model found`
написано `MISSING` — значит модуль ищет комнаты, а здание ещё не построено
или атрибуты `RoomId` не проставлены.
